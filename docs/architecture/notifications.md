# Slack通知

送信関数は [`src/infrastructure/notification/slack_notify.py`](../../src/infrastructure/notification/slack_notify.py) にあります。通知送信に失敗しても取引などの本処理を止めず、ログに記録します。`process_notification()`は開始・終了をログに記録し、例外時に設定されていればLLM原因分析を行ったあと例外を再送出します。`notify_lifecycle=True`の場合に限って開始・終了通知を送信し、異常終了は`critical`へ送ります。現行entrypointの多くは`notify_lifecycle=False`で、機能ごとに結果を個別送信します。

| チャンネル | 送る機能 | 送る時刻 | 内容 |
|---|---|---|---|
| `daily` | スクリーニング | 平日15:35または手動実行時 | 採用数、価格・規制による除外数、候補の活発度など |
| `daily` | フィルタリング | 平日09:30または手動実行時 | 採用数、評価数、理由コード件数、通過銘柄の活発度など |
| `daily` | 取引開始 | 平日取引処理の開始時 | 取引モード、対象銘柄数、市場条件・傾向文 |
| `daily` | 取引中間報告 | 既定11:30、14:00（設定変更可） | 注文件数、損益、保有、判定イベント、市場状況など |
| `daily` | 注文・取引結果 | 注文成立時、取引終了時 | 注文詳細、日次レポート、保有・損益・強制売却確認 |
| `daily` | 日次タスク予定・実行確認 | 運用資料記載の毎朝07:00・18:00 | 当日の予定、実行状況。要確認: OSタスク登録状況 |
| `daily` | J-Quants運用結果 | オーケストレーション終了時（定期・手動実行） | 実行日、全体/各段階の状態、補填処理日数、予算到達、終了コード |
| `daily` | 上場銘柄マスタ更新 | 土曜09:00または手動実行時 | JPX取得銘柄数、マスタ行数、更新日、保存先 |
| `analysis` | 日次・週次・月次分析 | 平日既定16:30、土曜10:00、月末最終取引日17:00 | 分析結果、対象期間、集計状態、答え合わせ |
| `analysis` | 分足バックフィル・バックテスト | 土曜07:30・08:00、または手動実行時 | 取込結果、バックテスト成績・結果への参照 |
| `analysis` | 戦略レビュー | 手動実行時 | 仮説生成・検証結果。失敗時は失敗箇所と詳細 |
| `critical` | 取引の緊急系イベント | 発生時 | キルスイッチ、API認証復旧失敗、全銘柄の板取得連続失敗、注文成立、強制決済未完了、新規買い停止、状態ファイル保存失敗 |
| `critical` | タスク・処理の異常 | 実行結果確認時または例外終了時 | タスク実行要確認、`notify_lifecycle=True`の異常終了 |

取引中間報告の既定時刻は`TRADING_PROGRESS_REPORT_1_HOUR/MINUTE`と`TRADING_PROGRESS_REPORT_2_HOUR/MINUTE`で設定できます。取引開始通知には`MarketRegime`評価に基づく市場条件・傾向文を加えます。スクリーニングとフィルタリングの完了通知にも候補・通過銘柄の活発度を加えます。

日次・週次・月次分析、バックテスト、日記、戦略レビューでLLM機能が有効な場合、生成内容をそれぞれの結果通知に含めることがあります。LLMそのものに別のSlackチャンネルを割り当ててはいません。

通知チャンネルは`SLACK_WEBHOOK_DAILY`、`SLACK_WEBHOOK_ANALYSIS`、`SLACK_WEBHOOK_CRITICAL`に対応します。`process_notification()`の終了通知は、異常時以外の通常entrypointでは個別通知に置き換えられている場合があります。
