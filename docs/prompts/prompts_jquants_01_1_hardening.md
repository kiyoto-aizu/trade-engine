# PR1.1：J-Quants V2クライアントのハードニング（差分最小）

## 目的
PR1で実装済みのJ-Quants V2クライアントについて、
曖昧なエラー分類・秘匿漏れ・ページング異常系を最小差分で補強する。

## 前提
- 対象リポジトリ：kiyoto-aizu/trade-engine
- PR1で追加済み：
  - `jquants_v2_client.py`
  - `config.py` のJ-Quants設定
  - `test_jquants_v2_client.py`
  - 関連ドキュメント
- 実API接続、コミット、プッシュは行わない
- 既存の未コミット差分は壊さない

## やること（最小差分）

### 1) エラー分類の明確化（断定しない）
実APIの範囲外エラーが400/403等で揺れる可能性があるため、
「契約範囲外」を断定する分類は行わない。

#### 要件
- ステータス分類は少なくとも以下に分離：
  - `AUTH_ERROR`（401相当）
  - `PERMISSION_OR_CONTRACT_ERROR`（403相当）
  - `CLIENT_REQUEST_ERROR`（その他4xx）
  - `RATE_LIMITED`（429）
  - `SERVER_ERROR`（5xx）
  - `TRANSPORT_ERROR`（接続/タイムアウト）
  - `RESPONSE_SCHEMA_ERROR`（data/pagination_key不正）
- 400は原則 `CLIENT_REQUEST_ERROR` とし、
  契約範囲外だと断定しない
- エラー本文の文言に依存した分岐を追加しない

### 2) 秘匿の最終強化（ログ・例外）
例外やログに機密や生本文を含めないことを、実装とテストで保証する。

#### 要件
- 例外メッセージに以下を含めない：
  - APIキー
  - Authorization/x-api-keyヘッダー値
  - レスポンス本文（JSON全体、HTML全体）
  - pagination_key
  - クエリ文字列全体（必要ならマスク）
- ログ出力は安全な最小情報のみ：
  - endpoint名（安全な識別子）
  - status code
  - attempt
  - wait seconds
  - page index / count（可能なら）
- `raise ... from ...` の連鎖で生本文が露出しないようにする

### 3) ホスト固定・リダイレクト保護のテスト補強
#### 要件
- 非公式ホスト指定時は即エラー
- HTTP→HTTPSや別ドメインへのリダイレクトに自動追従しない
- いかなるケースでもAPIキーを許可外ホストへ送らない
- 上記をモックテストで確認（実通信なし）

### 4) ページング異常系の保証
#### 要件
- `pagination_key` 循環を検知して異常終了
- `data` 欠落/型不正は `RESPONSE_SCHEMA_ERROR`
- 途中ページ失敗時は「部分成功」を返さない
- 呼び出し元パラメータ不変（破壊的変更なし）

## テスト追加・更新
`test_jquants_v2_client.py` を中心に、以下を追加/強化する。

1. 400は `CLIENT_REQUEST_ERROR` に分類される
2. 403は `PERMISSION_OR_CONTRACT_ERROR` に分類される
3. 例外文字列・ログに機密/本文/pagination_keyが含まれない
4. 非公式ホスト拒否
5. リダイレクト不追従
6. ページキー循環検知
7. data型不正で `RESPONSE_SCHEMA_ERROR`
8. 途中失敗で部分成功なし

既存テストの意図を壊さず、命名と構造を合わせること。
