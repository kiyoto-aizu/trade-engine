# PR3：指定日の全銘柄取得とcanonical Parquet化

## 目的
指定した1営業日の日足または分足について、
全銘柄のAPI取得 → raw確定 → canonical Parquet確定まで実装する。

日次更新と過去補填で共有する「1日単位の処理」を作る。
今回は実装とモックテストまで。実APIによる取得は実行しない。

## 対象・作業制約
- 対象：kiyoto-aizu/trade-engine
- リモートと作業ディレクトリを確認する
- 既存の未コミット変更・削除・未追跡ファイルを保持する
- 実API接続、.env内容確認、コミット、プッシュは禁止
- テストは合成データとテンポラリ領域のみ
- 無関係な変更・大規模リファクタリングは禁止

## 完了済みの基盤
- jquants_v2_client.py：認証、ページ取得、再試行、レート制御
- jquants_raw_store.py：raw、台帳、不変世代、公開・復旧処理
- 再取得中・失敗後も旧公開世代を保持する
- 非空の公開世代に対する空の再取得はEMPTY_HELD
- 公開途中の停止からrecover_dataset()で復旧できる
- Windows専用ロック
- Windowsで関連64テストが成功、failed/skipともに0

これらを実コードで確認して利用する。
同じ機能を重複実装しない。
PR2.1の再設計を始めず、新たな不具合が見つかった場合だけ報告する。

## 1. 取得・変換ユースケース
入力：
- dataset：daily / minute
- date：対象日
- refresh：明示的なraw再取得
- canonical-only：確定rawからの再変換、通信禁止

全銘柄取得ではdateのみをAPIへ指定する。
現在の銘柄マスタやフィルタ結果による絞り込みは行わない。

処理：
1. 対象データセットの未完了公開処理があれば既存APIで復旧
2. 確定rawを再利用、またはページ取得してraw確定
3. 公開されたraw世代を検証済み読み出しAPIで解決
4. rawからcanonicalを生成・検証・確定
5. 集計だけの安全な実行サマリを返す

既存のロックと整合するように実装し、二重取得を防ぐ。
稼働中の別プロセスを復旧処理が奪わないこと。

## 2. 公開世代の参照【重要】
- 最新の取得試行と公開済み世代を区別する
- datasets.content_sha256を公開世代のhashとみなさない
- published_generation_idを基準とする既存の
  検証済み読み出しAPIを利用する
- CURRENTやDB列を独自に読んで世代選択しない
- 不整合を無視して処理を続けない

EMPTY_HELDの場合：
- 新しい空取得をcanonicalの入力にしない
- 以前の公開世代を保持する
- 今回の再取得でデータが更新されたとは報告しない
- 要確認状態をサマリに残す

EMPTY_HELDを取得失敗・正常更新と混同しない。
未完了一覧とは別に、要確認一覧で参照できるようにする。

## 3. 仕様の根拠
先行調査の仕様：
- daily：/equities/bars/daily
- minute：/equities/bars/minute
- date指定で全銘柄、dataとpagination_keyによるページング
- 日足：Date, Code, O, H, L, C, UL, LL, Vo, Va,
  AdjFactor, AdjO, AdjH, AdjL, AdjC, AdjVo等
- 分足：Date, Time, Code, O, H, L, C, Vo, Va
- 分足Time：JSTの1分区間開始時刻

既存資料・公式資料と照合する。
アクセスできなかった公式ページを確認済みと説明しない。
未確認の細部は記録し、実API試験前の確認事項へ残す。

推測によるフィールド名の吸収や、
必須項目の欠落を黙ってNoneへ変換する処理は行わない。

## 4. canonicalスキーマ
固定のPyArrowスキーマを定義する。

日足：
- Codeを文字列として保持
- 日付
- 調整前OHLC、出来高、売買代金
- 調整係数
- 調整済みOHLC、出来高
- 確認済みのその他提供項目

分足：
- Codeを文字列として保持
- 日付
- JSTの区間開始時刻
- OHLC、出来高、売買代金

共通：
- 0とNoneを区別する
- 英字を含むコードを保持する
- 全列nullでも列型を安定させる
- 型・精度・null許容の方針を文書化する
- 未知の項目はrawへ保持し、未対応項目を把握できるようにする
- 分足の分割調整、欠落バー補完、特徴量計算は行わない

既存MinuteBarや既存Parquetを無理に拡張しない。

## 5. 保存・来歴
既存Yahoo/自前データと保存先を分離する。
全銘柄を日付単位のデータセットとして保存する。
銘柄×日付の小ファイル構成は採用しない。
大きな日付データは複数partにできる構造でよい。

来歴：
- raw世代IDと内容hash
- schema_version
- transformer_version
- 生成時刻
- 行数、銘柄数
- 品質検査結果

raw確定とcanonical確定を別状態として管理する。
canonicalはstagingへ作成し、検証後に有効版を切り替える。
以前の確定canonicalは、新版の変換失敗で失わない。

同じraw世代・schema版・transformer版の再実行は冪等にする。
変換失敗後はrawの再取得なしで再変換できること。

## 6. 品質検査
- 対象日とレコード日付の一致
- 必須キー、型、日付・時刻形式
- dailyの一意キー：Code + Date
- minuteの一意キー：Code + Date + Time
- OHLC関係、負の出来高などの異常
- ページをまたぐ重複
- rawからcanonicalへの件数整合

完全一致重複と、同一キーで値が異なる競合を区別する。
競合をlast-write-winsで黙って消さない。
品質不合格の場合、canonicalを確定しない。

現在マスタにないコードを不要として削除しない。
バーがないだけで、無取引・取得漏れを断定しない。
歴史的な上場廃止銘柄まで網羅したと保証しない。

## 7. メモリ・再検証コスト
- ページ単位の取得・raw読み出しを活用する
- 全件を複数のリストへ重複展開しない
- 必要に応じてParquetWriter等でバッチ保存する
- 読み出し世代は処理単位で解決し、
  行・銘柄ごとに全raw再ハッシュを呼ばない
- hash検証を省略するキャッシュの導入は今回必須ではない
- 重複検査などでメモリを使う箇所と、その増え方を報告する

## 8. CLI
既存構成に合わせてエントリーポイントを追加する。

引数：
- --dataset daily|minute
- --date YYYY-MM-DD
- --refresh
- --canonical-only

日付は厳密に検証する。
矛盾する引数の扱いを定義する。
APIキーをCLI引数で受け取らない。

終了状態：
- 正常完了
- 空結果・EMPTY_HELD等の要確認
- 取得・変換失敗

サマリ：
- dataset、対象日、状態
- raw/canonical世代
- 新規取得か既存raw利用か
- ページ数、行数、銘柄数
- 検証異常・重複件数
- 保存サイズ
- 取得・検証・変換の所要時間
- 警告

株価レコード、APIキー、ページキー、raw本文は出力しない。
旧世代を利用した場合は、その事実を明示する。
