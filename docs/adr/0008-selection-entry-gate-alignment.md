# ADR-0008: 選定・買い条件・ATR安全ゲートの向きを揃える

## ステータス

提案 / 2026-10-19(観測フェーズから着手。実装は未着手)

## 背景・課題

トレンド売買型の戦略として約定数が少ない。直近の分析で次が分かった。

- 約定が少ない主因は、見送りの約7割を占める **ATR DANGER見送り**
  (`ATR_DANGER_RATIO=2.0`以上、`ATR_DANGER_ACTION=skip`、
  `trading_usecase.py`の買い数量調整で数量を0にしている)
- 価格帯を上げるだけでは解決しない。450/900円帯は注文上限(30,000円)で
  100株を買えない銘柄が多く、値幅の差も補完後は小さい
- DANGER銘柄を外すと、買いシグナル自体が減った

ここから、次の2つの構造的な不整合が課題として特定された。

### 課題1: 選ぶ段階と買う段階の向きが逆

- 選定段階(値上がり率などの順位)は、**勢いの強い銘柄**を上位に選ぶ
- 買う段階のATRゲートは、**ATR比2.0以上(勢いが強すぎる銘柄)** を見送る
- 結果、選定で上位に選んだ銘柄が、買う段階で弾かれる

### 課題2: 買い条件(勢い)と安全ゲート(勢い過多を避ける)の衝突

- 買い条件は勢い(トレンド・RSIなど)を要求する
- 安全ゲートは勢いが強すぎる状態を避ける
- 両方を同時に満たす領域が狭く、シグナルが減る

## 決定

方針は「買う段階の抑止・停止側を見直す」。ただし**今回は観測のみ**とし、
挙動を変える実装は、観測結果を確認してから別途決める。

### 観測フェーズ(今回の範囲)

課題ごとに、挙動を変えずに影響を定量化する。

1. 課題1: 選定結果(上位N銘柄)のうち、買う段階で `atr_danger_skip` になった割合を
   日別・銘柄別に集計する。既存の `SelectionAtrObserver`
   (`selection_atr_observer.py`)と `ATR_DANGER_SKIP` のフィルタ判定記録を
   使い、選定順位とATRレベルの対応を出す
2. 課題2: 買いシグナル成立時のATRレベル(NORMAL/CAUTION/DANGER)の分布と、
   DANGER見送り後の観測価格の推移(見送らなければ得られた損益)を比較する。
   既存の `ATR_DANGER_SKIP` 記録(見送り後の観測価格)を使う
3. 分析は `scripts/analysis/` の分析スクリプトで行い、本番・バックテストの
   ロジックは変更しない

### 実装フェーズ(観測後に判断・未決定)

観測結果次第で、以下を比較して選ぶ。

| 案 | 課題1への効果 | 課題2への効果 |
|---|---|---|
| 選定段階でATR DANGER銘柄を除外する | 選定とゲートが揃う | なし |
| `ATR_DANGER_ACTION=minimum`(DANGERでも最小単位で買う) | 弾かれなくなる | ゲートが緩む |
| ATR閾値を引き上げる(例: 2.0→2.5) | 弾かれる数が減る | ゲートが緩む |
| トレンド戦略用にゲート基準を分ける(順行の上昇は許容、逆行・急落のみ見送り) | 弾かれる数が減る | 向きの衝突を解消 |
| 買い条件側にATR上限を持たせシグナルを揃える | なし | シグナルとゲートが揃う |

## 検討した代替案

- **価格帯を引き上げる**: 却下。注文上限で100株を買えない銘柄が増え、値幅の差も小さい
- **DANGER銘柄を単純に外す**: 却下。買いシグナル自体が減ったため
- **観測せずに閾値を緩める**: 保留。DANGER見送り後の損益が未確認で、
  緩めた結果の損失リスクを評価できない

## 影響・トレードオフ

- 観測フェーズでは本番・バックテストの挙動は変わらない
- 実装案はいずれも損切り幅・ロットとの兼ね合い(ADR-0002、ADR-0006の
  `ATR_STOP_DANGER_MULTIPLIER`など)があり、ゲートを緩める場合は
  DANGER時の損失拡大を別途評価する必要がある
- 観測期間が短い・上昇相場に偏る場合は、結果の一般化に注意する
