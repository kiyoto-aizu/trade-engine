# 第三者レビュー要否の判断基準（案）

目的: 変更の性質に応じて、第三者レビュー（`wf:review-needed`）の要否を判断する。
同系統のモデルによる自己レビューは、前提や盲点を共有しやすい。リスクが高い変更ほど独立した目を入れる。
ラベル運用は `docs/label-operation-rule.md` に従う。最終判断（Go / Rework）は人間が行う。

## 1. 必須（第三者レビューを依頼する）
次のいずれかに該当する変更。

- 実売買・発注・資金/ポジション計算に関わる
- 認証情報・APIキー・秘密情報の扱い、公開レポート（`trade-report`）への出力経路
- 有料データの保存・公開境界（raw/canonical の確定、世代管理、削除）
- データの破壊的変更（schema の非互換変更、既存データの書き換え/削除）
- 実API接続を伴う新規の処理
- 判定基準・閾値・運用方針など、人間の判断を左右する設計の新規決定
- 無人実行・自動再実行・スケジューラの導入
- API利用量・レート・リトライ設定の変更
- 依存パッケージの追加、CIの権限変更
- ロック・並行制御・再開処理で、公開境界に触れるもの

## 2. 推奨（人間が判断。迷ったら依頼）
- 新規モジュール追加（読み取り専用で外部影響なし）
- 既存ロジックの挙動変更（バグ修正でも影響範囲が広い）
- テストでカバーしにくい並行制御・ロック・再開処理（公開境界に触れない場合）

## 3. 不要（セルフチェックのみ）
次をすべて満たす変更。

- ドキュメントの誤字・表現・軽微な追記
- テストの追加・修正のみ（本体変更なし。既存の期待値の変更・削除は除く。実質的な仕様変更のため）
- 影響が単一ファイル内に収まり、既存テストで検証できるごく小さな修正
- 秘密情報・データ・実売買に無関係

## 4. セルフチェック（レビュー不要の場合も実施）
- 関連テストが pass している
- 出力・ログに秘密情報、株価レコード、銘柄コードが含まれない。「出ない」ことを確かめるテストがある
- 生成物がGit管理外であることを確認している（`git check-ignore`）
- 実API接続・Yahoo系への暗黙フォールバックを導入していない
- PR 本文に `Refs #番号` を記載（`Closes` は使わない）

## 5. 指摘の重大度とマージ条件
- 重大: 秘密情報の漏えい、データ破壊、誤った判定で実害が出うるもの、設計と実装の根本的な不一致
- 中: 一部の条件で誤動作する、設計が未定義で運用時に判断が割れる
- 軽微: 表現・使い勝手・テストの網羅性
- 重大が未解決のPRはマージしない。中は対応するか、別Issueとして記録してからマージする

## 6. 運用
- 要否はエージェントが提案し、人間が決める。判断に迷う場合は必須側に倒す
- レビュー不要とした場合も、PR/Issue に「基準 3 に該当、セルフチェック実施」と1行記録する
- エージェント自身の自己レビューは第三者レビューの代替にならない。補助として使う
- 「第三者」は、作成者と別の主体（人間、または作成に関わっていない別系統のモデル）とする
- レビュー結果はPRコメントに残す。依頼時は、対象コミット・前提・観点・差分（または全文）を添える

## 7. レビュー依頼テンプレート
```
<repo> の PR #<番号> を第三者レビューしてください（Issue #<番号> に対応）。
【対象コミット】<sha>
【前提】<実API接続の有無、閾値が初期値かなど>
【観点】<判断の妥当性、論理バグ、秘密情報の流出、テストの抜け など>
重大度（重大/中/軽微）をつけて指摘してください。
```
